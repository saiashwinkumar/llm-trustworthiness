Sources and methods

The presentation uses a read-only, immutable local snapshot of the authoritative AWS continuation. Its files are separate from the experiment and the queue’s own reports. Complete newline-terminated records were copied in child-before-parent order. Record hashes, dataset identity, parent references, saved prompts, and measurements were checked before rendering.

Files

  • Computed findings, source IDs, prompt cohorts, and sample sizes
  • Verification results
  • Read boundaries and source hashes
  • Independent numeric, link, and partial-record checks
  • Model revision, inference settings, dataset and run provenance
  • Saved execution plan and subset assignments
  • Cases and household split assignments
  • Full prediction inputs and outputs
  • Full explanation prompts, responses, and preserved assessments
  • All intervention records, including measured and skipped records
  • Audit worksheet (blank fields are not evidence of human review)

Interpretation

All counts refer to effective records in this continuation. Historical source records nested under original_record are provenance, not extra observations. Predictions use normalized conditional answer-sequence likelihoods, not calibrated probabilities of customer purchases. The main presentation uses choice accuracy and observed answer changes, not answer-score metrics.

Fixed-brand baseline: fit the most frequent product on development only. Support baseline: choose the modal product across the five unordered support purchases. Ties use sorted candidate IDs, as in the project evaluation. Baselines are evaluated on the same purchases as the corresponding model column. Test interpretation is exploratory because an earlier pilot inspected test outcomes. No fine-tuning is recorded.

Counterfactual summaries exclude skipped records. Removal denominators count purchases; order denominators count actual reorderings and explicitly identify distinct purchases. Random controls are count/type matched but can overlap cited evidence. The builder only calls a control uncited if its IDs are disjoint from the citations, and compares those controls within purchase before averaging purchases. It requires five measured random removal controls before a paired case contributes. A missing uncited comparison is not filled in.

Example selection: retain the development workflow example when available; choose the first paired incorrect test example in saved response order. Edited-input illustrations show the four requested categories: cited removal, comparable uncited removal, a price edit, and presentation order. The cited/uncited pair shares its original prediction and explanation and removes equal counts of each evidence type. A saved keep-cited measurement qualifies as uncited removal when its actual masked complement is wholly uncited and matches those counts; this is verified from the edited evidence. Price and ordering examples are the first measured with-history records, falling back to either condition. Selection does not require the answer to change. Exact saved prediction and explanation prompts are displayed, with original whitespace and precision. Counterfactual highlights mark changed lines; the complete original and edited prompt text is retained. These are illustrative measurements, not a representative error-rate sample. The derived uncited pair is reported separately from the five-random-control aggregate.

Explanation cohorts and policy

  • common-evidence-v3: 4 responses
  • common-evidence-v2: 2 responses
  • common-evidence-v4-unlimited-citations: 236 responses

The current citation policy is available-evidence-unlimited-v1. The original JSON schema is retained; JSON readability, required fields, existing IDs, and duplicate citations are separate checks. Original raw text, prompts, and earlier assessments remain in the records. Older explanation prompts were not regenerated. Eligibility for evidence interventions does not establish correctness or faithfulness.

Refresh

From the project root:

.venv/bin/python -B scripts/build_presentation_report.py --refresh-aws

This reads EC2 using the existing SSH identity. It makes no model calls and performs no remote writes. Omit --refresh-aws to rebuild from the last saved snapshot. If SSH or validation fails, the published page stays unchanged. Open presentation/index.html locally, or unzip presentation/choice-study-presentation.zip for the page and all linked sources.
